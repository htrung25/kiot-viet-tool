# CLAUDE.md

Avalonia desktop app (.NET 10) shipped to customers as one self-contained Windows `KiotVietTool.exe`. Future goal: integrate the KiotViet public API.
Dev machine is macOS: the app runs there too (`dotnet run`), the release exe is tested on a Windows VM. UI text is Vietnamese.
Business model (2026-10-05, supersedes `docs/SRS_v3.md`, which is outdated background only): time-bound % / VND discounts are set up only in the tool; KiotViet prices are **never written**. A Chrome extension on the cashier's KiotViet web POS adds the discount to the invoice-level "Giảm giá" field when the cashier presses Thanh toán / F9, so scanning shows the original price and the QR / printed invoice show the discounted total. Repo parts: `src/` (tool), `feed/` (Cloudflare Worker + KV holding the discount feed), `extension/` (Chrome MV3), `relay/` (Telegram relay).

## Commands

```bash
dotnet build                                                     # must stay at 0 warnings
dotnet run --project src/Desktop                    # launch the UI (Debug: F12 = DevTools)
dotnet publish src/Desktop -p:PublishProfile=win-x64   # → artifacts/publish/win-x64/
dotnet tool restore && dotnet ef migrations add <Name> \
  -p src/Infrastructure -s src/Infrastructure -o Persistence/Migrations
```

The repo has no test projects (removed deliberately by the owner; do not add them unless asked).
Verify with `dotnet build`, a throwaway script in your scratchpad (file-based `dotnet run x.cs` with
`#:project` + `#:property PublishAot=false`), and by launching the app and checking the log. Screen capture is not available,
so verify UI by rendering headlessly (see "Verify UI visually" below). Windows-only code paths (P/Invoke to user32) are guarded by `OperatingSystem.IsWindows()`.

## Architecture (Clean Architecture)

Dependency rule: `Desktop → Infrastructure → Application → Domain`. Never reference the other way.
Folders are `src/<Layer>/` (short names); project files, assembly names and namespaces keep the `KiotVietTool.<Layer>` prefix.

Key decisions:
- **Repositories use `IDbContextFactory`**: each method is its own short-lived DbContext (no long-lived context in a desktop app). Entities returned are detached; `UpdateAsync` attaches via `Update()`.
- **Validation lives in the Domain entity**; Application services catch `DomainException` and return `Result.Failure`. Services never throw for expected business errors.
- **Time** via `TimeProvider`, which `AddApplication` registers as `ServerClockService`: machine clock + offset measured from KiotViet `Date` headers (every API response, plus an unauthenticated `HEAD` when the reading is > 10 min old, every minute from `DiscountFeedSyncService`). So every "now" is estimated KiotViet time; a skew ≥ 2 min shows a banner in the shell. The extension uses the Worker's `Date` header the same way.
- **Navigation is ViewModel-first**: `INavigationService.NavigateToAsync<TVm>(parameter)` sets `CurrentViewModel`; `MainWindow`'s `ContentControl` renders it through `Application.DataTemplates` in `App.axaml`. VMs override `ViewModelBase.OnNavigatedToAsync`. Screens never navigate to an unrelated screen by type just to "go home": use `NavigateHomeAsync()`; which screen is Login / ChangePassword / Home is declared once as `NavigationRoutes` in `App.CreateHost`.
- **Dialogs** only through async `IDialogService` (Avalonia has no MessageBox; `Views/MessageDialogWindow` implements it). Confirm with a question title, the consequence as message and a verb on the button (`ConfirmAsync("Dừng chương trình?", "...", "Dừng chương trình", destructive: true)`), never a bare "OK".
- **Success feedback** is a toast via `INotificationService.ShowSuccess` (non-blocking); errors that need attention use a dialog or an inline `Border.alert.error`.
- **Startup**: `Program.Main` does the single-instance check (named Mutex: `Local\` on Windows, `Global\` on Unix because Unix `Local\` is per process session; activation signal via named pipe) and defines `%LOCALAPPDATA%` on non-Windows. `App.OnFrameworkInitializationCompleted` registers global exception handlers (`Dispatcher.UIThread.UnhandledException`, `AppDomain`, `TaskScheduler`), builds the Generic Host (`UseContentRoot(AppContext.BaseDirectory)`, Serilog) and shows `MainWindow` from DI; on `Opened` it starts the host, runs `InitializeDatabaseAsync()` (→ `Persistence/DatabaseInitializer`: migrate + seed default admin) and navigates to Login.
- **Auth** (single local account): `UserAccount` in SQLite, password hashed with PBKDF2-SHA256 (`Infrastructure/Services/Pbkdf2PasswordHasherService`, 600k iterations, format `v1.<iterations>.<salt>.<hash>` Base64; legacy `pbkdf2-sha256$...` still verifies). `Verify` trusts nothing from the stored string: known version, exact 16-byte salt, exact 32-byte hash (output length is a constant), iterations 100k–10M; anything else is rejected and logged as a warning (never log the hash). `NeedsRehash` is true for legacy/older version/fewer iterations; `AuthService.SignInAsync` then re-hashes the password best-effort via `UserAccount.UpgradePasswordHash` (keeps `MustChangePassword`; a failed save never blocks sign-in). To strengthen hashing later: raise `Iterations`, or add a `v2` with its own sizes and keep parsing `v1`. Default admin comes from `Auth:DefaultAdminUsername/Password` in appsettings and is seeded only when the table is empty, with `MustChangePassword = true`. `IUserSessionService` (singleton, Application) holds the signed-in user; only `IAuthService` and `ITelegramService.ConfirmAsync` change it. `NavigationService` is the auth guard: not signed in → `LoginViewModel`, temporary password → `ChangePasswordViewModel`, `NeedsTelegram` → `TelegramSetupViewModel`; view models reachable anonymously implement `IAnonymousViewModel`. Telegram 2FA (FR-AUTH-08…10): when a `TelegramConnection` exists, `SignInAsync` does not set the session but sends a 6-digit OTP (`PendingSignInService`, in memory only: 5 min, 5 tries, resend after 60 s) and returns `OtpRequired`; `VerifyOtpAsync` / `SignInWithRecoveryCodeAsync` finish sign-in. 10 failures on the account → `OtpLockedUntilUtc` +15 min. With no connection the session gets `NeedsTelegram = true` and the guard keeps the user on the setup wizard (full screen, no sidebar while `IsMandatory`); `TelegramService` verifies the store's own bot token (DPAPI-encrypted), finds the chat from the latest private `/start` via `getUpdates`, confirms a code, then issues 10 recovery codes (hashed `s1.salt.hash` in `UserAccount.RecoveryCodeHashes`, shown once). `TelegramApiService` never logs URLs (the token is in the path); `Telegram:ProxyUrl` exists for networks blocking Telegram; alternatively `Telegram:ApiBaseUrl` points at the Cloudflare Worker relay (`relay/telegram-relay.js`, deployed from the repo root `wrangler.jsonc` by Cloudflare Workers Builds): it forwards only `getMe`/`getUpdates`/`sendMessage` for bot ids listed in the dashboard variable `ALLOWED_BOT_IDS` (`keep_vars`, so deploys never wipe it), passes Telegram's status and body through unchanged, and has observability off because the token is in the path. Unlocking the idle lock needs only the password. Idle lock (FR-AUTH-05, `Desktop/Services/IdleLockService`): wall-clock based (`TimeProvider`, so a sleeping PC locks on wake), activity = tunnel key/pointer events on `MainWindow`, paused while a sync runs; locking overlays `LockScreenView` over the disabled shell instead of signing out, so unsaved input survives; 5 wrong unlock passwords sign out.
- **Config**: `appsettings.json` is excluded from the single-file bundle and sits beside the exe. `%LOCALAPPDATA%` is expanded in `Database:Path` and in the Serilog file path; use `/` separators (works on both OSes). Serilog `"Using"` must list sink assemblies (single-file cannot scan).
- **Paging & sorting** (`Application/Common/Pagination`, `Common/Sorting`): `PageRequest` clamps on init (Page 1–100 000, PageSize 1–100) — read `Page`/`PageSize`/`Skip` directly, there is no "unsafe" value. `PagedResult<T>` has a private constructor: build it only via `Create(items, request, total)`, `CreateWithoutTotal(itemsPlusOne, request)` (query `PageSize + 1` rows when `IncludeTotal` is false) or `Empty(request)`; `TotalPages`/`HasNext` are computed, never set. Convert entities to DTOs with `Map`. Filters are separate per-entity DTOs (not in `PageRequest`); sort with `SortRequest<TField>` over a per-entity enum in `Application/Enums/` and always add `.ThenBy(x => x.Id)` for a stable order. `Skip` maps to KiotViet's `currentItem`. Page-number buttons ("…") are UI-only (`Desktop/Models/PageLink`).
- **KiotViet API** (`Infrastructure/Services/KiotVietApiService`, singleton, own `HttpClient`, GET only): token cached per Client ID+Secret, refreshed ≤ 60 s before expiry and once on 401; GET limited in memory to `KiotViet:MaxGetRequestsPerHour` (sliding hour); 429/5xx/timeout retried `MaxRetries` times (1-2-4 s or `Retry-After`); every failure becomes `KiotVietApiException` with a Vietnamese message (SRS Phụ lục B). KiotViet datetimes have no offset and mean UTC+7: convert with `Application/Common/VietnamTime`; the DB stores UTC (a convention in `AppDbContext` marks every `DateTime` as UTC on read). Client Secret is stored via `ISecretProtectorService` (DPAPI on Windows, `dev:` Base64 fallback on macOS dev only).
- **Catalog sync** (`CatalogSyncService`, singleton, one run at a time): categories and price books are fetched in full, products incrementally (`lastModifiedFrom` = last sync − 5 min, `removeId` → `IsDeleted`), items of non-expired price books in full; everything is written by `ICatalogRepository.ApplySyncAsync` in one transaction (cancel = old data kept). KiotViet ids are the primary keys of `Category`, `Product`, `PriceBook`.
- **Discount programs**: pricing in `DiscountProgram.Quote` (exclusions → compute; no rounding, KiotViet rounds the invoice discount). Lifecycle stored as `ProgramStatusEnum` Draft → Published → Stopped; the shown phase (`PhaseAt`: Nháp / Sắp diễn ra / Đang chạy / Đã kết thúc / Đã dừng) is derived from the clock. `StartMode` Immediately sets `StartAtUtc` on publish; `EndAtUtc` ≥ start + 5 min, minute precision, UTC. Only drafts are editable / deletable; "Huỷ áp dụng" before start returns to Draft. `DiscountProgramService` resolves scope (categories include children; a chosen product brings its other units) and blocks overlaps with other Published, not-ended programs.
- **Discount feed** (`DiscountFeedService`, singleton, one operation at a time): Activate / Stop / ChangeEnd save the program, then build the feed (`GetFeedProgramsAsync`: Published, not ended, product ids after exclusions) and `PUT` it to the Worker (`DiscountFeedApiService`, `DiscountFeed:Url` + `WriteToken`) only when its hash changed; a failed push is kept in `Status.LastError` (warning banners) and retried every minute by `Desktop/Services/DiscountFeedSyncService`, which also catches catalog changes and programs passing their end. Worker `feed/discount-feed.js`: `GET/PUT /v1/feed`, Bearer `READ_TOKEN` / `WRITE_TOKEN` secrets, KV key `feed`, light validation. Extension: `background.js` fetches every minute into `chrome.storage`; `bridge.js` (isolated) posts it to the page; `discount.js` (pure, Node-testable) reads cart lines (first array of `activeCart` with `ProductId` + `Quantity`, price `Price ?? BasePrice`), computes per line and decides; `pos.js` (MAIN world), on any click inside `payment-invoice-component` (payment methods, QR), a Thanh toán / QR button, or F9, calls the payment controller's `adjustDiscount` (found via `angular.element(node).data()` walking up from `button.form-discount`) inside `$apply`, resets to 0 when the lines change afterwards, never overwrites a manual discount, and applies nothing when the feed is older than 30 min. The KiotViet server accepts invoice discounts from cashier accounts whose discount permission is off (UI-only lock). Upgrading from the basePrice model: `DatabaseInitializer` refuses to migrate while old `ProgramProductPrices` rows still hold discounted prices.
- Central Package Management: versions only in `Directory.Packages.props`; `dotnet add package` writes there automatically.

## Code rules

- **Folder layout rules (layer-based)**: inside each project, files are grouped by kind (`Entities/`, `Interfaces/`, `Services/`, `DTOs/`, `Repositories/`, `Options/`, `Views/`, `ViewModels/`, `Models/`...), not by feature. Namespace = folder path. One main type per file, file name = type name. `Common/` only for cross-cutting building blocks (Result, Pagination, Sorting). **The type name must carry its folder's kind**: `Services/` → `*Service` (interface `I*Service` in `Interfaces/`), `Repositories/` → `*Repository`, `DTOs/` → `*Dto`, `Options/` → `*Options`, `Exceptions/` → `*Exception`, `ViewModels/` → `*ViewModel` (incl. marker interfaces such as `IAnonymousViewModel`), `Views/` → `*View` (UserControl) or `*Window` (Window). `Entities/`, `Models/` and `Enums/` have no suffix. If a type doesn't fit a folder's suffix, it belongs in another folder (e.g. `NavigationRoutes` is configuration data → `Models/`).
- `sealed` by default, file-scoped namespaces, primary constructors where natural.
- async/await end to end with `CancellationToken`; never `.Result` / `.Wait()` / `.GetAwaiter().GetResult()`.
- No business logic in code-behind or ViewModels; ViewModels only call Application services.
- MVVM via CommunityToolkit.Mvvm partial properties: `[ObservableProperty] public partial T X { get; set; }` and `[RelayCommand]` on `async Task XAsync(CancellationToken)`.
- No hardcoded config values; use `appsettings.json` + `IOptions<T>` (bind + validate in the layer's `DependencyInjection.cs`).
- Nullable warnings are errors (`Directory.Build.props`). Keep `dotnet build` at 0 warnings; unused usings (IDE0005) and broken doc `cref`s are reported, fix with `dotnet format style KiotVietTool.slnx --diagnostics IDE0005 --exclude src/Infrastructure/Persistence/Migrations`.
- Namespace gotcha: inside `KiotVietTool.*`, `Application` resolves to the `KiotVietTool.Application` namespace; write `Avalonia.Application` explicitly in Desktop.
- **UI design system**: colors only from `Resources/Colors.axaml` tokens (`{StaticResource Text.Muted}`, `Primary`, `Danger`...), never hex in views; icons are `PathIcon` with `Icon.*` geometries from `Resources/Icons.axaml` (Material Design Icons). Style classes in `Resources/Styles.axaml`: buttons `accent` (primary, Fluent), `secondary`, `danger`, `ghost`, `icon`; text `h1`, `h2`, `subtitle`, `caption`, `label`; layout `Border.card`, `Border.divider`, `Border.alert.error|warning`, `StackPanel.field` (label above input), `Grid.page` (page margins). Pages inside the shell = header (h1 + subtitle + primary action on the right) then a card; lists need an empty state and a no-results state. `ShowChrome` in `MainViewModel` hides the sidebar for full-screen flows (login, forced password change).
- **Verify UI visually**: render screens headlessly (Avalonia.Headless + Skia, `CaptureRenderedFrame()`) from a throwaway scratchpad script and inspect the PNGs at 1200×760 and the 960×600 minimum; don't ship layout changes unseen.
- Avalonia: styles use selectors + classes (`Resources/Styles.axaml`); a selector list must target one control type (no `TextBlock, PathIcon` sharing a setter); `DataGridTextColumn` needs its own `x:DataType`; no MouseBinding, so double-click is forwarded to a command in code-behind (view glue only).
- Keep `PublishTrimmed=false` (EF Core, DI and Serilog configuration rely on reflection).
